# 当前知识库治理与使用规范

本文件是当前库唯一的内容治理规则。与 `runtime-policy.json` 或程序校验冲突时，以当前实现中更严格且可验证的规则为准。

## 1. 内容分层

| 层级 | 内容类型 | 可以做什么 | 不可以做什么 |
|---|---|---|---|
| 产品事实 | `product_facts` | 支撑当前10个正式型号的参数、功能与限制 | 不得跨型号、跨系统或自由组合SKU |
| 竞品资料 | `competitor_*` | 比较任务中提供检索入口、对比维度和待核事实 | 未重新打开品牌官网前，不得形成当前竞品结论 |
| 表达参考 | 场景、话术、范文、支持资料 | 提供受众问题、文章结构、语气和核验提示 | 不得升级为产品事实或客户真实经历 |
| 商业资料 | `business_rule`、`historical_price_snapshot` | 规定动态字段的登记方法，并支持历史价格分析 | 空模板或历史价格不等于当前政策与当前数值 |
| 图片素材 | 精确型号、通用 | 精确型号图可按登记说明配图 | 通用图片不得自动绑定型号 |
| 派生视图 | `派生视图/` | 横向查找字段和定位原始事实 | 不作为独立证据，不单独维护事实值 |

## 2. 证据顺序

1. 当前任务对应的完整型号、SKU、系统/软件版本、地区、渠道和日期。
2. 当前官方产品页、规格页、支持页或已核验的内部动态记录。
3. `catalog.json` 中哈希一致的本地事实原文。
4. 场景、话术、案例和派生视图只能帮助查找、组织和表达。

来源冲突时保留冲突并停止确定性结论，不按更新时间、措辞强弱或文件数量自行投票。官网页面若出现明显字段错位，可以在目录中登记“来源纠正”，但必须同时保存原路径、原哈希、纠正值、官方交叉来源和核验日期。

## 3. 检索与调用

- 先锁定主推产品，再读取该型号的 `product_facts`；相似型号不视为同一型号。
- 常规营销任务不检索竞品资料。只有用户明确提出比较、替代或点名竞品时，才进入竞品层。
- 促销、报价、库存、补贴、交付或权益任务才检索商业动态层；模板只提供流程，具体数值必须来自未失效记录。
- 产品发现卡用于判断“是否值得补库”，不能替代正式规格。
- 每轮默认最多使用1份产品事实、2份表达参考和2张精确型号图片；数量限制以 `runtime-policy.json` 为准。
- 派生视图必须能回到产品事实文件及其哈希。源文件变化后重新生成，不手工修补派生值。

## 4. 首次使用复核

文字资料首次进入稿件前，复核其对象、条件、来源、内部一致性和可用边界。审核缓存必须绑定文件哈希、记录元数据、依赖事实、提示词、模型和规则版本；任一变化均重新复核。

- `passed`：允许在本次声明的范围内使用，不代表官网实时核验或人工批准。
- `uncertain`：资料有价值但不足以支持确定结论，本次排除。
- `rejected`：资料不应进入生成。
- `failed/in_progress`：不得放行，也不得把失败结果写成通过。

产品事实摘录必须是原文中的连续片段，只允许排版空白差异。参考材料即使包含参数，也只按参考使用，不能绕过产品事实层。

## 5. 图片规则

- `registered_image`：来源或画面证据能够绑定精确型号，可进入该型号配图候选。
- `general_image`：通用场景、服务或活动素材，不绑定型号，当前不自动使用。
- 检索配图时，先按精确型号进入 `05-图片素材/<型号>/`；该文件夹内的图片即视为已归属该型号，直接依据文件名中的中文画面说明选择展示内容，不再通过文件名是否含型号做二次确认。
图片只能证明可见画面；不能证明续航、性能、兼容性、护眼效果、价格或用户体验。图注不得比登记说明和产品事实更强。

## 6. 竞品比较

比较对象必须落到具体品牌、完整型号、配置、地区和日期。使用同一维度、同一口径和同一证据时点，不用华为的具体SKU对竞品系列泛称，也不把旧价、第三方评论或案例写成当前官方事实。

对外比较前至少重新核对：在售状态、处理器/内存/存储组合、屏幕、接口、重量、电池、系统、服务和价格口径。无法同步核验的维度删除或明确写成待核验，不输出“全面领先”等总括结论。

## 7. 商业动态

本地库保存业务规则和历史价格。历史价格只用于时间趋势、变动追溯和制定核验清单；具体价格、库存、赠品、补贴、交期、返利或项目政策必须另行取得当前有效记录，并同时具备：完整SKU、值与单位、地区、渠道、适用对象、来源、核验时间、生效/失效时间和复核状态。

缺少任一会改变结论的字段时，只能输出核验清单或请人工确认。历史价格不得改写成“目前”“现价”或长期承诺。

## 8. 发布前检查

- 型号、年份、系统、SKU、正文、图片和链接一致。
- 每个数字、功能、兼容、服务和比较结论都有同段可追溯依据及必要条件。
- 未把范文写成真实体验，未把场景假设写成客户案例。
- 动态信息仍在有效期内，口径与目标地区、渠道、对象一致。
- 图片归属、插入位置和图注正确，未从画面推导不可见事实。
- 平台篇幅、结构、标签、图片数量和行动引导符合当前配置。
- 不确定项已删除、降级表述或明确转人工，不用“仅供参考”掩盖猜测。

## 9. 更新规则

正文变化必须同步更新记录哈希和相关来源信息；来源、型号归属或纠正记录未同步时拒绝读取。新事实进入权威文件，派生索引重新生成。已失效内容从运行库删除；确有项目追溯价值时放入项目根目录的 `archive/`，不得留在运行库。

每次结构调整后运行 `python tools/validate_knowledge_base.py`，再运行相关回归测试。结构校验通过只证明文件和索引一致，不代表全部内容已完成官网实时核验。

## 10. 产品事实文件结构约定

- 文件骨架固定为：来源 → 官方规格摘录 → 操作系统 → 尺寸与重量 → 屏幕 → 处理器 → 存储 → 显卡（官网列出时）→ 内存 → 无线连接 → 电池 → 接口 → 键盘和触控板 → 摄像头 → 音频 → 特色应用（官网列出时）→ 包装清单。台式机按官网保留 `光驱`、`电源`、`键盘和鼠标` 等章节，章节顺序以官网为准。
- 参数行统一为 `参数名：值`；同一参数有多个状态时重复参数名，状态后的冒号按原文保留；脚注留在原位置。
- 参数名只取原文已有名称或章节名，不新造。同义参数统一：`处理器`（不用 `CPU`）；`显卡`（集成显卡写作 `显卡：集成显卡：…`）；`亮度`（峰值写作 `亮度：峰值亮度：…`）。
- 尺寸参数名与顺序照各产品官网原文（如 `长度/宽度/厚度`、`宽度/深度/高度`、`高度/宽度/深度`），不跨产品统一、不改名、不重排；官网标签与数值顺序异常时，按物理含义配对数值并保留「字段映射纠正」注记。
- 触控板条目统一以 `触控板：` 开头。
- 接口节统一为一行一个端口、以 `接口：` 开头；原文的分组限定（位置/系统/形态）作嵌套前缀，其余位置细节保留在括号内（如 `接口：左侧：USB-C × 1`、`接口：Windows 版：USB-C × 1（左侧）`）；端口名称、数量、功率和脚注不改。
- 例外：键盘、特色应用等条目式章节暂按原文句子保留，待逐项定规则；音频的扬声器、麦克风条目统一写作 `扬声器：…`、`麦克风：…`；包装清单只保留产品条目，网页导航等非产品文本应删除。
- 官网未列出的章节不补造；缺节不视为漏抓。
