每条参考的 `usage` 标明它该用来学什么；参考只提供写法与人群语言，不提供产品事实。

要求：

1. `opening` 必须同时填写非空的 `title` 和 `intro`；`body` 必须按平台篇幅把它写成完整小节：标准篇幅通常 2 至 3 个段落、合计约 300 字，长文正文块更多，短文案（朋友圈、海报）按平台要求保持简短；`closing` 必须填写非空的 `cta`，并按平台要求填写 `tags`。其他职责字段返回空值。没有图片时 `images` 返回空数组，不要因此拒绝生成文字。
2. 正文只能引用当前块 `fact_ids` 白名单内的事实编号。参数、功能、性能、兼容性、价格和权益必须有事实支持。
3. 已通过块只用于衔接，不得修改、复制无依据主张或引入新事实。
4. 图片只能使用清单内 ID；`caption` 逐字复制清单中的 `registered_caption`。按平台策略尽量用足图片数量，已通过块用过的图片不要重复使用；图片在当前正文块内的 `after_paragraph` 从 0 开始计算。
5. 不能安全满足的要求写入 `refusals`，不得编造。
6. 标题、导语和行动引导如果没有可引用的事实，只能表达受众、场景和阅读引导，不得写入产品参数、功能或效果主张。
7. 当 `opening.fact_ids` 为空时，标题和导语不得出现事实清单中的任何数字、规格、产品属性、功能、适配性或效果；只能复述规范需求中已确认的受众、场景、关注问题与阅读引导。例如可以写“开学季选电脑，先看清日常学习需求”，不能写“轻松装进背包”“减轻通勤负担”或任何重量、厚度、屏幕参数。
8. 正文必须完整保留所用事实中的配置、测量方式、适用范围和差异说明。若完整条件不适合当前篇幅，就不要使用该事实；不得把有限条件压缩成无条件结论，也不要从参数推导“更轻松”“更清晰”“提升效率”等使用效果。
9. 返回且只返回如下结构的合法 JSON，不要使用 Markdown 代码围栏或附加说明。所有字段都必须保留：

{
  "title": "",
  "intro": "",
  "body": [
    {"text": "正文段落", "fact_ids": ["F1"]}
  ],
  "cta": "",
  "tags": [],
  "images": [
    {"image_id": "I1", "after_paragraph": 1, "caption": "登记图注", "reason": "选择理由"}
  ],
  "refusals": []
}
