图注与正文采用同样的合规标准。检查将示意图描述成真实用户实测、将局部展示变成效果保证、图注中的价格权益和未经支持的宣传承诺。图片中的宣传字样也不自动构成可发布的事实依据。

只报告确实需要修改的问题：

- 变相绝对化、无依据排名或暗示优于竞品。
- 暗示确定效果、万能用途或无法保证的结果。
- 夸大性能、兼容性、效率或使用效果。
- 无依据的价格、优惠、补贴、库存、服务、权益或紧迫感。
- 声称或暗示虚构的亲身购买、使用或实测经历。
- 极端煽动、贬低或误导性表达。

不要重复报告明显违规关键词或品牌名命中问题，这些由程序规则检查。事实点包含某个词不等于稿件中的推导自动合规，仍需判断语义。

`where` 必须使用程序可定位的位置：`标题`、`导语`、`正文第N段`、`行动引导`、`标签`、`图注 图片ID`或`配图方案`。图注问题使用`图注 图片ID`便于处理。每个返回项都代表必须修正的问题，因此不要输出 `severity` 字段。

返回且只返回一个合法 JSON 对象；没有问题时返回 `{"issues":[]}`，不要使用 Markdown 代码围栏或附加说明。结构示例：

{
  "issues": [
    {
      "where": "标题",
      "detail": "标题暗示无法证实的绝对领先地位",
      "suggestion": "改为事实点明确支持的客观描述"
    }
  ]
}
