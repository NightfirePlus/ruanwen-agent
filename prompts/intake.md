## 抽取要求

根据对话记录，尽可能准确地抽取以下信息，输出JSON格式：

### 1. product (具体型号)
- 优先识别**完整型号名称**（如"MateBook X Pro"、"MateBook D 14"）
- 如果用户只说了系列或类型（如"华为笔记本"、"轻薄本"），**留空**，不要猜测
- 如果用户提到多个型号，在`llm_notes`中说明需要确认
- **示例**："MateBook X Pro" / "MateBook D 16" / ""（未明确）

### 2. product_type (产品类型)
- 判断产品大类：轻薄本 / 全能本 / 游戏本 / 商用本 / 平板 / 台式机
- 可以从用户描述的需求推断（如"带去学校用" → 轻薄本）
- **示例**："轻薄本" / "全能本" / ""

### 3. audience (人群判断)
- 识别目标人群或使用者
- 常见人群：大学新生 / 职场人士 / 创作者 / 家庭用户 / 企业采购 / 学生家长
- **示例**："大学新生" / "商务人士" / "设计师" / ""

### 4. scene (场景)
- 尽量匹配到"场景选项"中的标准场景
- 如果没有明确提及，根据人群和时间推断（如10月+学生 → 开学季）
- 无法判断时留空
- **示例**:"开学季" / "职场办公" / "内容创作" / ""

### 5. platform (平台)
- 尽量匹配到"平台选项"中的标准平台
- 识别关键词：公众号/推文/文章 → 公众号；小红书/笔记/种草 → 小红书；朋友圈/门店 → 朋友圈；海报/展架 → 门店海报
- **示例**:"小红书" / "公众号" / "朋友圈" / "门店海报" / ""

### 6. goal (目标)
- 判断内容目标，选择以下之一：
  - **种草**：让用户产生兴趣、了解产品
  - **转化到店**：引导到店体验、咨询
  - **咨询引导**：引导私信、留言、加微信
  - **促销告知**：告知活动、优惠、新品
- **示例**:"种草" / "转化到店" / "咨询引导" / "促销告知"

### 7. stage (购买阶段)
- 判断目标用户的决策阶段，选择以下之一：
  - **初步了解**：刚开始了解，不熟悉产品
  - **对比选购**：在多个产品间对比选择
  - **犹豫观望**：有兴趣但还有顾虑
  - **需求明确**：明确要买，需要选择具体型号
- 根据人群和场景推断（如新生→对比选购，商务→需求明确）
- **示例**:"对比选购" / "需求明确" / ""

### 8. main_problem (用户最关心的问题)
- 用一句话概括用户最关心的核心问题
- 从对话中提取，不要编造
- **示例**:"续航能不能撑一整天" / "适不适合视频剪辑" / "会不会太重" / ""

### 9. extra (临时要求)
- 用户的特殊要求或补充说明
- 如"要提到多屏协同""不要太长""要有价格信息"等
- **示例**:"要突出多屏协同功能" / "篇幅控制在500字以内" / ""

### 10. llm_notes (综合判断说明)
- 你对当前信息的综合判断
- 说明推理过程、不确定的地方、需要确认的信息
- 如果信息不足，说明缺什么
- **示例**:"用户提到开学季和学生，推断为大学新生开学场景。平台未明确，建议确认。"

---

## 注意事项

1. **不要猜测型号**：如果型号不明确，`product`留空，在`llm_notes`中说明
2. **尽量匹配标准选项**：`scene`和`platform`优先从提供的选项中选择
3. **字段名不要改**：输出JSON的字段名必须与要求一致
4. **留空用空字符串**：不确定的字段填`""`，不要填`null`或省略
5. **不要生成追问**：只负责抽取信息，不要在这里生成追问内容（程序会根据规则决定是否追问）
