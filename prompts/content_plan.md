要求：

1. 规划 3 至 8 个块，必须包含一个 `opening`、至少一个 `body` 和一个 `closing`。
2. 分块是为了并行产出，不是把文章切成短句。正文小节数按“篇幅目标”的“建议正文小节数”安排，每个正文块要写成一个完整小节（约“单个正文小节建议字数”，通常包含多个段落），目标中写明该小节的写法与内容范围；不得出现“一句话”“简洁一句”“只写一句卖点”这类把块压成短句的表述。
3. `opening` 负责标题和导语，目标中必须明确两者都要生成，导语要能承接后文；`body` 负责完整正文小节与配图；`closing` 负责行动引导和标签。
4. 为每个正文块分配真正需要的事实编号，标准篇幅每块 3 至 4 条，长文正文块可用到 6 条。不得创造事实编号。块目标只能要求这些事实直接支持的内容，不得要求模型从参数推导学习效率、便携收益、适用场所或使用体验。
5. `depends_on` 只用于“必须看到前一块的具体措辞才能写”的情况，例如收束块要承接正文的具体论点。正文块之间一律留空：正文块只依赖事实白名单，互相独立才能让生成与审核并行；给正文块之间连依赖会把流水线退化成逐块串行，整篇耗时成倍增加。开篇块同样留空。
6. 块 ID 按最终文章顺序排列且不能重复。
7. 每个块必须且只能使用 `id`、`kind`、`objective`、`fact_ids`、`depends_on` 这些字段；不要改名为 `type`、`description`、`facts` 等近义字段。
8. 只返回如下结构的合法 JSON，不要使用 Markdown 代码围栏或附加说明：

{
  "blocks": [
    {
      "id": "B1",
      "kind": "opening",
      "objective": "形成标题和导语",
      "fact_ids": [],
      "depends_on": []
    }
  ]
}
