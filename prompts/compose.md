## 生成要求

1. **严格遵守策略**：按照"内容策略"中的场景切入点、卖点顺序、平台要求生成内容

2. **事实必须标注**：
   - `body`数组中每个段落包含`text`(文字)和`fact_ids`(引用的事实编号数组)
   - 涉及产品参数、功能、性能的段落必须标注事实编号，如`["F1", "F3"]`
   - 纯引导语、过渡段落可以`fact_ids`为空数组

3. **图片必须匹配**：
   - `images`数组中每张图片必须指定：
     - `image_id`: 来自"可用图片"列表的ID
     - `after_paragraph`: 插入位置(0=开头, 1=第1段后, 2=第2段后...)
     - `caption`: 图片说明(简短描述图片内容)
     - `reason`: 为什么选这张图(说明与段落内容的关联)
   - 严格遵守平台的图片数量要求(min-max范围)

4. **输出完整JSON**，包含以下字段：
   ```json
   {
     "title": "标题文字",
     "intro": "导语或开头一句话",
     "body": [
       {"text": "第1段正文", "fact_ids": ["F1", "F2"]},
       {"text": "第2段正文", "fact_ids": ["F3"]}
     ],
     "cta": "行动引导文字",
     "tags": ["标签1", "标签2"],
     "images": [
       {
         "image_id": "I1",
         "after_paragraph": 1,
         "caption": "图片说明",
         "reason": "选择理由"
       }
     ],
     "refusals": []
   }
   ```

5. **无法满足的情况**：
   - 如果事实不足以支持用户要求，在`refusals`数组中说明
   - 如果可用图片少于平台最低要求，在`refusals`中说明
   - 如果场景与产品定位明显冲突，在`refusals`中说明
   - **不要强行生成不符合要求的内容**

## 注意事项

- 标题、正文、CTA必须符合平台的篇幅、语气、结构要求
- 所有产品信息只来自事实点清单，不得自行补充
- 图片ID必须来自可用图片列表，不得编造
- 输出纯JSON，不要包含markdown代码块标记
- 确保JSON格式正确，可以被程序解析
