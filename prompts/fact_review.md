你的任务是对生成的营销软文进行事实核验，检查语义层面的事实问题。

**注意**：程序已经用规则核验了数值、型号、图片归属等明确问题，你只需要检查**规则无法发现的语义问题**。

## 核验重点

只检查以下**语义层面**的问题，不重复规则已检查的内容：

### 1. 事实引用是否支持表述
- 稿件中的表述是否被所引用的事实点真正支持
- 是否存在过度推理或夸大解读
- **示例问题**：
  - 事实："支持10点触控"
  - 稿件："触控响应极快" ← 事实没说"快"
  - 判断：error，事实不支持

### 2. 条件和限制是否完整
- 性能数据、续航时间是否说明了测试条件
- 兼容性、适配性是否说明了适用范围
- **示例问题**：
  - 事实："本地视频播放可达14小时（实验室条件下，50%亮度）"
  - 稿件："续航14小时" ← 丢失了测试条件
  - 判断：warn，建议补充条件

### 3. 功能描述是否准确
- 功能的实际作用是否与稿件描述一致
- 是否暗示了事实中没有的功能
- **示例问题**：
  - 事实："支持与手机协同"
  - 稿件："无缝连接所有设备" ← 扩大了范围
  - 判断：error，超出事实范围

### 4. 对比和排名是否有依据
- "更轻""更快""领先"等对比表述是否有事实依据
- 是否暗示了排名或市场地位
- **示例问题**：
  - 稿件："比同类产品更轻薄"
  - 事实清单中无对比数据
  - 判断：error，无依据的对比

### 5. 适用场景是否合理
- 推荐的使用场景是否符合产品定位
- 是否暗示了不在事实中的用途
- **示例问题**：
  - 产品：轻薄本
  - 稿件："适合3D渲染" ← 轻薄本通常不适合
  - 判断：warn，场景不匹配

### 6. 因果关系是否成立
- "所以""因此"等推理是否合理
- 是否建立了不成立的因果关系
- **示例问题**：
  - 稿件："屏幕是OLED，所以续航更长" ← 因果关系错误
  - 判断：error，因果关系不成立

## 不需要检查的内容（规则已覆盖）

- ❌ 数值是否与事实完全一致（规则已检查）
- ❌ 型号名称是否正确（规则已检查）
- ❌ 图片是否属于该型号（规则已检查）
- ❌ 绝对化用语、虚假承诺（合规检查环节）

---

## 严重程度判断

- **error**：明显事实错误，必须修改
  - 事实不支持的表述
  - 超出事实范围的声明
  - 无依据的对比或排名
  - 因果关系错误

- **warn**：潜在问题，建议修改
  - 丢失重要条件或限制
  - 场景不完全匹配
  - 表述不够准确但不算错误

---

## 输出格式

输出JSON数组，每个问题包含：
- `where`: 问题位置（如"标题"、"正文第2段"、"图片说明"）
- `severity`: 严重程度（"error"或"warn"）
- `detail`: 具体问题描述
- `suggestion`: 修改建议

**没有问题时返回空数组**`{"issues":[]}`

```json
{
  "issues": [
    {
      "where": "正文第3段",
      "severity": "error",
      "detail": "稿件称'触控响应极快'，但事实点只说明'支持10点触控'，没有关于响应速度的信息",
      "suggestion": "删除'极快'，改为'支持10点触控'的客观描述"
    },
    {
      "where": "正文第5段",
      "severity": "warn",
      "detail": "提到'14小时续航'，但事实点中明确是'本地视频播放、实验室条件、50%亮度'，稿件丢失了测试条件",
      "suggestion": "补充测试条件，如'本地视频播放可达14小时'"
    }
  ]
}
```
