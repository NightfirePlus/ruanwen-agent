只报告确实需要修改的问题：

- 某段引用的事实不能支持其结论、形容或因果关系。
- 表述扩大了功能、适用范围、性能或对比结论。
- 遗漏配置、测试条件、兼容范围等会改变原意的重要限制。
- 使用场景或效果声明没有事实点支持。
- 将第三方结论写成官方事实。

不要重复报告纯数值匹配、事实编号是否存在、型号名称或图片归属问题，这些由程序规则检查。不要把纯文风偏好当成事实问题。

`where` 必须使用程序可定位的位置：`标题`、`导语`、`正文第N段`、`行动引导`、`标签`或`配图方案`。每个返回项都代表必须修正的问题，因此不要输出 `severity` 字段。

返回且只返回一个合法 JSON 对象；没有问题时返回 `{"issues":[]}`，不要使用 Markdown 代码围栏或附加说明。结构示例：

{
  "issues": [
    {
      "where": "正文第2段",
      "detail": "该表述超出了所引事实的适用范围",
      "suggestion": "删除超出范围的结论，只保留事实明确支持的内容"
    }
  ]
}
