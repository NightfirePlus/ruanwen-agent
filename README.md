# 华为PC营销软文智能体

**[查看项目进度与下一步](ROADMAP.md)** · [当前运行约定](docs/knowledge-runtime.md) · [魔搭部署](README_MODELSCOPE.md)

当前：界面、知识库、多模型分工及首次使用审核已完成，下一步进行实际导购稿质量验证。知识库固定为 `knowledge_base/current`，进度与约定直接更新，不另存版本。

面向华为PC门店与内容运营的自研 Agent。产品事实与图片只从本地知识库目录读取；Agent 负责理解需求、匹配资料、套用场景与平台策略、生成图文、核验事实、检查合规,并在确认环节按用户意见局部重做。知识库接口统一为本地读取，不再需要远程知识库服务或其凭证。

## 流程

```
1 多轮追问 ─▶ 结构化需求 ─▶ 2 知识库匹配资料 ─▶ 3 策略表匹配 ─▶ 4 图文生成
                                                                    │
        ┌──────────── 有问题:改写,最多 2 轮 ◀── 5 事实核验 + 6 合规检查 ◀┘
        ▼
   7 确认环节 ── 确认 ─▶ 定稿
        ├─ 文案不满意 / 临时要求 ─▶ 回到 4(资料、策略复用)
        ├─ 换场景 / 换平台 ───────▶ 回到 3(资料复用,换策略表)
        └─ 换产品 ────────────────▶ 回到 1(全部重来)
```

| 阶段 | 代码 | 方式 | 要点 |
|---|---|---|---|
| 1 结构化需求 | `agent/intake.py` | LLM 抽取与判断,规则判定是否完整 | 场景/人群/平台/目标/购买阶段/核心问题;缺项或型号太笼统就追问,是否完整不信任 LLM 自述 |
| 2 资料匹配 | `agent/catalogkb.py` | 规则 + LLM + 审核缓存 | 型号精确匹配，首次使用只复核文字；登记图片按精确型号直接选用，事实保留来源 |
| 3 策略匹配 | `agent/strategy.py` | 查 `config/*.json` | 场景表给切入点、卖点顺序、禁区;平台表给标题/篇幅/结构/语气/图片数/行动引导 |
| 4 图文生成 | `agent/compose.py` | LLM | 卖点必须标注事实编号;图片只能选确认属于该型号的 |
| 5 事实核验 | `agent/fact_check.py` | 规则 + LLM | 数值、型号、图片归属、数量由规则核对;LLM 只能新增问题,不能撤销规则发现的问题 |
| 6 合规检查 | `agent/compliance.py` | 规则 + LLM | 词表与正则 + LLM 找隐性问题;无依据的价格权益一律拦截 |
| 7 确认与修改 | `agent/revise.py` | LLM 判断意图,规则决定重跑起点 | 意图不明确就追问,不乱改 |

调度在 `agent/pipeline.py`,返回状态:`need_more_info` / `need_choice` / `blocked` / `review` / `done`。

## 安装与运行

需要 Python 3.10+，先运行 `pip install -r requirements.txt`。

配置可写入项目根目录的 `.env`，也可使用系统环境变量；两者都有时系统环境变量优先。`.env` 已被 `.gitignore` 排除。

| 变量 | 说明 |
|---|---|
| `LLM_API_KEY` | 大模型 Key(OpenAI 兼容接口) |
| `LLM_BASE_URL` | 大模型接口地址,默认阿里云百炼公共端点 |
| `LLM_MODEL` | 模型名,默认 `qwen-plus` |
| `LLM_PROFILE` | 默认 `modelscope-v1`，三模型按阶段分工；可显式设为 `single` |
| `MODELSCOPE_API_TOKEN` | 分工模式的魔搭令牌；也可沿用填有魔搭令牌的 `LLM_API_KEY` |
| `KB_LOCAL_DIR` | 默认使用 `knowledge_base/current`；可指定当前知识库的实际存储位置 |
| `PROMPTS_DIR` | 可选，指向另一套提示词目录；默认使用项目内的 `prompts/` |

不要把任何凭证写入代码、README、截图或演示视频。当前知识库随项目上传，令牌、本地配置和运行时审核数据库不提交。

当前分工：Qwen3.5-35B-A3B理解需求，Qwen3.5-397B-A17B写作，GLM-5.2复核文字资料与成稿。图片暂不调用视觉模型，只使用知识库中已登记且绑定精确型号的素材。文字首次使用审核结果保存在库内SQLite，资料或规则变化后重新审核。新库强制严格核验，分工模式关闭接口自动重试与JSON修复。详见 [运行约定](docs/knowledge-runtime.md)。

```bash
python main.py                                  # 多轮对话
python main.py "给大学新生写一篇 MateBook 14 的小红书"
python main.py --allow-unfinished-prompts       # 提示词没写完时先跑通其余部分
python run_tests.py                              # 运行全部测试
```

每次运行默认把完整记录(含每个阶段的输入输出)保存到 `samples/`,用 `--no-save` 关闭。

## 提示词

代码里不写任何提示词文字,全部在 `prompts/`,一个环节一个文件,每个文件开头的注释写明可用变量与输出契约。

| 文件 | 阶段 | 使用 `writer_system.md` |
|---|---|---|
| `writer_system.md` | 软文写作的系统提示词(手册要求的 8 个模块) | — |
| `intake.md` | 1 结构化需求 | 否 |
| `evidence.md` | 2 摘录事实点 | 否 |
| `material_review.md` | 新库首次资料复核 | 否 |
| `image_review.md` | 已停用，保留供以后恢复视觉审核时参考 | 否 |
| `compose.md` | 4 图文生成 | 是 |
| `fact_review.md` | 5 事实核验(LLM 部分) | 否 |
| `compliance_review.md` | 6 合规检查(LLM 部分) | 否 |
| `revise_intent.md` | 7 判断修改意图 | 否 |
| `rewrite.md` | 按问题改写 | 是 |

- 模板用 `{{变量名}}` 引用程序提供的内容;`<!-- ... -->` 注释发给模型前剥离。
- 输出 JSON 的字段名是程序读取结果的依据,改文字可以,改字段名要同步改代码。
- 骨架里带“待补充”的文件视为未完成。默认启动时一次性列出全部未完成项并拒绝启动;`--allow-unfinished-prompts` 下,调用到未就绪环节才报错,事实核验和合规检查的 LLM 部分会明确提示“已跳过”,规则部分照常工作。
- 平台与场景的具体规则在 `config/*.json`,每次生成自动注入,提示词里不需要重复写。

## 网页工作台

`python app.py` 启动三栏创作工作台：左侧展示场景判断与知识库依据，中间以聊天为主并支持切换图文预览，右侧展示核验结果与下载入口。真实阶段摘要在当前聊天回复内实时更新，完成后保留为可展开的处理记录。输入框固定在中间底部；产品、人群、场景与目标从框内的“创作设置”向上展开，发布平台可直接选择，统一使用同一个发送入口。未修改的设置不会在后续对话中重复附加。

稿件通过阻断项检查后，可分别下载发布成品和完整溯源报告，格式包括 Markdown、DOCX 和 PDF。

本地未设置 `PORT` 时，从 7860 起自动选择空闲端口，访问启动日志中显示的地址即可。设置 `PORT` 后会固定使用该端口，适用于创空间部署。

## 已知限制

- 当前库按精确型号读取产品事实，检索相关人群与表达参考；范文、发现卡和历史价格不能升级为当前产品证据。图片暂不执行视觉内容审核，仅依赖登记归属、文件哈希、说明和用途；图片不能作为产品参数或效果依据。自动复核不等于重新核实官网或人工批准。
- 运行只使用 `knowledge_base/current` 及审核标记；旧库、旧快照和迁移链已经删除，`archive/` 不参与运行。全量官网事实、素材授权和实际营销效果仍需验证。部署时保持审核索引可写、可持久化。
