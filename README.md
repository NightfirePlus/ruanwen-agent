# 华为PC营销软文智能体

**[核心架构规范](docs/core-architecture.md)** · [查看项目进度与下一步](ROADMAP.md) · [当前运行约定](docs/knowledge-runtime.md) · [魔搭部署](README_MODELSCOPE.md)

当前：已将“多轮需求澄清—知识安全门禁—上下文装配—双模型分块队列—整文连贯性编辑—全文终审—确认归档”确立为目标核心架构。现有界面、知识库、多模型路由、整篇生成复核、历史作品、用户偏好与导出能力是迁移基础；分块队列、规范任务说明、知识有效期与官网文字核验尚待实现。知识库仍在整理，具体有效期按资料类型配置，数值待知识治理完成后确定。

面向华为PC门店与内容运营的自研 Agent。系统通过多轮对话明确目的并形成结构化需求和规范任务说明，匹配产品事实、卖点宣传模板与产品图片，再与门店偏好、按效果权重选出的历史优秀作品共同装配为写作上下文。产品事实与图片来自受控知识库；模板、偏好和历史作品只影响表达，不得作为产品事实。

## 目标核心流程

```
多轮追问 ─▶ 结构化需求 ─▶ 规范任务说明 ─▶ 知识安全门禁 ─▶ 上下文装配 ─▶ 文章分块规划
                                                                  │
                                                                  ▼
                    ┌─▶ 生成/重写模型 ─▶ 审核队列 ─▶ 审核模型 ──通过──▶ 已通过块
                    │        ▲                         │
                    │        └──── 需要重写的块 ───────┘
                    └──────────── 生成/重写队列
                                                                  │ 全部块通过
                                                                  ▼
                 整文连贯性编辑(不改变事实) ─▶ 全文终审 ─▶ 用户确认
                                                                  ├─ 修改：按影响范围回退
                                                                  └─ 确认：归档并多格式下载
```

分块阶段只有两个逻辑角色：生成/重写模型按队列持续生成内容块，审核模型并行消费已生成块；审核未通过的块作为结构化重写任务返回生成/重写队列。设计目的不是把文章机械切开，而是让生成与审核重叠执行，从而缩短总体等待时间。存在上下文依赖的块仍按依赖顺序处理。

| 阶段 | 目标方式 | 要点 | 当前状态 |
|---|---|---|---|
| 需求澄清 | 模型理解 + 规则确认 | 产品、受众、场景、平台、目标不明确就继续追问 | 已有结构化追问，待补规范任务说明 |
| 知识安全 | 内部审核 + 有效期 + 官网文字核验 | 新资料或过期资料由专用模型检查官方来源，错误或过时内容进入受控修订 | 已有内部审核缓存，TTL、联网核验和修订待实现 |
| 上下文装配 | 统一数据契约 | 事实、模板、图片、偏好和加权历史作品分权输入 | 部分已有，待收拢为核心模块 |
| 分块生产 | 双模型双向队列 | 生成/重写与审核重叠执行，问题块回重写队列 | 待实现；当前仍为整篇生成、整篇复核 |
| 整文编辑 | 事实锁定编辑 | 只改衔接、指代、语气和重复，不增删改事实 | 待实现 |
| 全文终审 | 规则 + 审核模型 | 检查组合后的事实、夸大、合规、图片与结构 | 已有整篇核验基础，待适配新链路 |
| 确认与回退 | 影响范围路由 | 修改时回到最早受影响阶段，只复用仍有效结果 | 已有粗粒度回退，待细化到知识、规划和内容块 |
| 归档与导出 | 确认后持久化 | 保存审核轨迹，提供发布成品和溯源报告 | 已实现基础能力 |

详细的数据边界、队列状态、知识修订规则和回退矩阵见 [核心架构规范](docs/core-architecture.md)。当前调度代码仍在 `agent/pipeline.py`，在代码迁移完成前继续返回 `need_more_info` / `need_choice` / `blocked` / `review` / `done`。

## 安装与运行

需要 Python 3.10+，先运行 `pip install -r requirements.txt`。

配置可写入项目根目录的 `.env`，也可使用系统环境变量；两者都有时系统环境变量优先。`.env` 已被 `.gitignore` 排除。

| 变量 | 说明 |
|---|---|
| `LLM_API_KEY` | 大模型 Key(OpenAI 兼容接口) |
| `LLM_BASE_URL` | 大模型接口地址,默认阿里云百炼公共端点 |
| `LLM_MODEL` | 模型名,默认 `qwen-plus` |
| `LLM_PROFILE` | 默认 `modelscope-v1`，三模型按阶段分工；可显式设为 `single` |
| `MODELSCOPE_API_TOKEN` | 分工模式的魔搭令牌；也可沿用填有魔搭令牌的 `LLM_API_KEY` |
| `KB_LOCAL_DIR` | 默认使用 `knowledge_base/current`；可指定当前知识库的实际存储位置 |
| `PROMPTS_DIR` | 可选，指向另一套提示词目录；默认使用项目内的 `prompts/` |

不要把任何凭证写入代码、README、截图或演示视频。当前知识库随项目上传，令牌、本地配置和运行时审核数据库不提交。

当前代码分工：Qwen3.5-35B-A3B理解需求，Qwen3.5-397B-A17B整篇写作与改写，GLM-5.2执行本地文字资料内部复核及整篇成稿核验。图片暂不调用视觉模型，只使用知识库中已登记且绑定精确型号的素材。内部审核结果保存在库内 SQLite，资料或规则变化后重新审核；这不等于官网实时核验。

目标分工增加专用知识核验角色，并将写作阶段改为生成/重写模型与审核模型之间的分块队列。具体物理模型可以调整，但两个队列角色、知识核验权限和事实边界保持不变。详见 [核心架构规范](docs/core-architecture.md) 与 [运行约定](docs/knowledge-runtime.md)。

```bash
python main.py                                  # 多轮对话
python main.py "给大学新生写一篇 MateBook 14 的小红书"
python main.py --allow-unfinished-prompts       # 提示词没写完时先跑通其余部分
python run_tests.py                              # 运行全部测试
```

每次运行默认把完整记录(含每个阶段的输入输出)保存到 `samples/`,用 `--no-save` 关闭。

## 提示词

以下为当前代码使用的提示词清单。代码里不写任何提示词文字，全部在 `prompts/`，一个环节一个文件，每个文件开头的注释写明可用变量与输出契约。实施目标架构时，还需补充规范任务说明、官网文字核验、文章规划、分块生成/审核、事实锁定连贯性编辑和全文终审的独立提示词及输出契约。

| 文件 | 阶段 | 使用 `writer_system.md` |
|---|---|---|
| `writer_system.md` | 软文写作的系统提示词(手册要求的 8 个模块) | — |
| `intake.md` | 1 结构化需求 | 否 |
| `evidence.md` | 2 摘录事实点 | 否 |
| `material_review.md` | 新库首次资料复核 | 否 |
| `image_review.md` | 已停用，保留供以后恢复视觉审核时参考 | 否 |
| `compose.md` | 4 图文生成 | 是 |
| `fact_review.md` | 5 事实核验(LLM 部分) | 否 |
| `compliance_review.md` | 6 合规检查(LLM 部分) | 否 |
| `revise_intent.md` | 7 判断修改意图 | 否 |
| `rewrite.md` | 按问题改写 | 是 |

- 模板用 `{{变量名}}` 引用程序提供的内容;`<!-- ... -->` 注释发给模型前剥离。
- 输出 JSON 的字段名是程序读取结果的依据,改文字可以,改字段名要同步改代码。
- 骨架里带“待补充”的文件视为未完成。默认启动时一次性列出全部未完成项并拒绝启动;`--allow-unfinished-prompts` 下,调用到未就绪环节才报错,事实核验和合规检查的 LLM 部分会明确提示“已跳过”,规则部分照常工作。
- 平台与场景的具体规则在 `config/*.json`,每次生成自动注入,提示词里不需要重复写。

## 网页工作台

`python app.py` 启动三栏创作工作台：左侧展示场景判断、事实与配图来源，中间只保留“对话创作 / 最新成果”，右侧展示核验结果与下载入口。历史作品和用户偏好统一挂载在右上角“账户信息”中，不与当前创作工作台混排。真实阶段摘要在当前聊天回复内实时更新，完成后保留为可展开的处理记录。输入框固定在中间底部；产品、人群、场景与目标从框内的“创作设置”向上展开，发布平台可直接选择，统一使用同一个发送入口。通过设置切换产品时会直接触发产品级重跑，不再依赖模型判断修改意图。

生成与归档分开处理：未确认前，“最新成果”始终展示当前会话的最新版本；用户明确确认定稿后，系统才把成品写入账户的历史作品库。历史作品可回看并修改标题、产品、人群、场景、平台、目标与正文，也可持续追加曝光、点赞、分享、咨询、到店与成交数据。宣传数据会按效果率、样本可信度及平台/场景/受众/目标/产品相似度计算参考权重；高表现作品优先影响后续内容角度、结构和 CTA，但永远不能作为产品事实、参数或承诺依据。用户偏好按当前账户保存常用语气、平台、重点客群、内容偏好与禁区，并自动用于后续创作。运行时数据默认保存在 `data/marketing_workspace.sqlite3`，也可通过 `WORKSPACE_DB` 指定其他路径；该数据库不会提交到 Git。旧版门店记忆会在首次启动时迁移为当前账户的用户偏好。

成品中的配图下方只显示“图一 / 图二……”及必要说明，不再重复图片文件名或来源；图片来源集中展示在左侧知识库依据卡片及内部核验链路中。

稿件通过阻断项检查后，可分别下载发布成品和完整溯源报告，格式包括 Markdown、DOCX 和 PDF。

本地未设置 `PORT` 时，从 7860 起自动选择空闲端口，访问启动日志中显示的地址即可。设置 `PORT` 后会固定使用该端口，适用于创空间部署。

## 已知限制

- 当前库按精确型号读取产品事实，检索相关人群与表达参考；范文、发现卡和历史价格不能升级为当前产品证据。图片暂不执行视觉内容审核，仅依赖登记归属、文件哈希、说明和用途；图片不能作为产品参数或效果依据。自动复核不等于重新核实官网或人工批准。
- 运行只使用 `knowledge_base/current` 及审核标记；旧库、旧快照和迁移链已经删除，`archive/` 不参与运行。全量官网事实、素材授权和实际营销效果仍需验证。部署时保持审核索引可写、可持久化。
