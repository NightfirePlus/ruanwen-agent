# 知识库与模型运行约定

本文件只维护当前约定，直接更新，不另存版本。项目进度统一见 [项目进度](../ROADMAP.md)。

## 数据与存放位置

唯一运行目录为 `knowledge_base/current`，可通过 `KB_LOCAL_DIR` 指定其他位置。原库及历史快照已退出运行，当前库可独立使用；清理状态见项目进度。

当前包含1030条资料：产品75、生态及支持160、人群场景162、营销表达452、图片112、动态信息69。可生成产品仍为10个已有完整事实的PC型号；55份扩展产品发现卡不能替代正式规格。

图片中53张有精确型号登记，59张归属未确认，不进入自动配图。动态信息包括66条历史价格及3份销售配置快照，不能作为当前价格、库存或权益。画像、范文、排障和营销参考不作为产品事实。

来源、行号、哈希和图片原索引记录保留在 `00-规范与索引/catalog.json`，产品来源表保留在该目录的 `来源登记/`，它们是必要追溯数据。`runtime-policy.json` 保存当前使用规则；`usage-review.sqlite3` 保存审核标记。不保存每次整理产生的报告或多份约定。

## 审核与复用

入库由外部负责。本项目执行：检索相关资料 → 检查版本与审核标记 → 仅审核未检查或已变化的资料 → 保存结论 → 写作 → 核验当前稿件。

审核记录绑定文件、标注、型号/配置、来源、相关产品依据、提示词、模型与规则版本。未变化则复用；文件修改需同步对应来源与catalog哈希，未同步则拒绝读取。原文只读，标记写入独立审核索引。

`passed`表示内部一致性与使用边界复核允许使用，不代表官网、授权或人工复核已经完成。`uncertain/rejected`复用为排除结果。失败或中断不得写成通过；并发请求先持久化占位，避免重复调用。

`python tools/knowledge_review.py` 查看当前标记。查明原因后，可用 `--reset 缓存key` 清除某条非通过记录，供下次使用重审；不自动发请求，不清除通过记录。

产品摘录必须能还原成连续原文；只允许排版空白差异，不接受改写。可疑尺寸字段隔离，不猜测正确数值。参考资料只提供表达与问题提示。每篇稿件仍检查当前型号、适用条件、图注与图文对应，素材曾通过不代表适合所有文章。

## 模型职责

| 模型 | 职责 |
|---|---|
| Qwen/Qwen3.5-35B-A3B | 需求理解、修改意图、实际图片审阅 |
| Qwen/Qwen3.5-397B-A17B | 图文写作、选图建议与局部改写 |
| ZhipuAI/GLM-5.2 | 首次资料复核、原文摘录、每篇事实与合规核验 |

实际图片以保留透明度的预览发送给视觉模型，输出画面、素材类型、主题和限制；不能独立使用的图层及不确定素材不放行。透明比例辅助判断，不能仅凭比例判坏图；文件有透明区域时，背景由发布容器决定。

写作接收已确认事实、表达参考、图片说明和视觉审阅记录。最终核验接收相关原文、排除内容和图片审阅，覆盖正文及图注。程序检查ID、型号、数量、重复与插入位置。新库强制严格核验。

## 成本与维护

默认每轮最多新增5次知识复核：产品事实1份、表达参考最多2份、图片最多2张。缓存齐备后不重复资料/图片审核；需求、写作和成稿核验照常。可通过 `KB_REVIEW_MAX_CALLS`、`KB_REFERENCE_LIMIT`、`KB_IMAGE_LIMIT` 收紧数量。

分工模式关闭接口重试与JSON自动修复；稿件问题最多改写两轮。未得到可用图片时明确说明，不编造素材凑数。审核模型仍可能出错，需用实际稿件持续验证。

`python tools/validate_knowledge_base.py` 校验当前库的文件、索引与内部链接，无需旧库，不调用模型。

当前库 `knowledge_base/current` 随仓库发布，历史快照、令牌和运行时审核数据库不提交。部署时让审核索引所在目录可写且持久化。模型或提示词调整后重启应用。
